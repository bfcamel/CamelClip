# Local library and S3

The queue, media library, S3 profiles and uploads live in the local `queue.sqlite3`. Global nonsecret limits remain in `settings.json`. Profile names, endpoints, buckets and prefixes are never exported into settings. Credentials are encrypted before SQL writes with AES-256-GCM and a fresh random nonce. Argon2id derives the key from the master password (64 MiB, three passes, two lanes); versioned parameters and salt are stored with the encrypted verifier. Profile IDs are bound into authenticated data. The master password and derived key are not saved, synchronized or put in Keychain.

Unlock is required in each process session. Automatic uploads default to off and wait for unlock after restart. Losing the password requires explicitly resetting profiles/credentials; local files and download history remain. A full database backup contains encrypted credentials and is confidential. Go cannot promise that every temporary copy of a decrypted string is immediately erased from RAM; no secrets are intentionally included in config output, errors or logs.

## Terminal controls

`1` jobs, `2` library, `3` uploads, `4` profiles. `c` opens CPU/RAM details; arrows scroll all logical CPUs. CPU sampling runs independently once per second; RAM used is total minus available as reported by the platform adapter. System measurements are session-only and do not alter `max(runtime.NumCPU()/4, 2)` processing slots.

Jobs: `Space` selects, `A` selects visible jobs, `p` pauses/resumes pending jobs, `[`/`]` set low/high priority, `=` normal, `<`/`>` move up/down, `{`/`}` first/last within priority. Active work is not paused or preempted; cancel and retry it. Bulk actions confirm their count and report each failure.

Library: `g` scans the configured folder nonrecursively, `i` imports an explicit file, `/` searches, `t` filters, `b` sorts, `v` refreshes metadata, `Enter` details, `f` plays, `o` reveals, `u` chooses upload profiles and reviews keys. `d` removes an index entry and excludes it from later scans; explicit import can add it again. `D` separately confirms physical deletion and its total size. History removal never deletes files. Missing files remain indexed as missing. Symlinks and staging files are skipped.

Profiles: `u` initializes/unlocks the vault, `n` adds, `e` edits, `k` replaces credentials, `t` tests bucket access without writing, `w` explicitly tests writing and cleanup, `a` toggles automatic uploads for future publications, `p` enables/disables, `m` rotates the master password atomically, `l` locks, `R` explicitly resets profiles. Profiles are saved only on this computer.

## CLI

```
camelclip queue list --json
camelclip queue add URL...
camelclip queue priority JOB_ID high
camelclip queue reorder JOB_ID first
camelclip queue pause JOB_ID
camelclip queue resume JOB_ID
camelclip queue retry JOB_ID
camelclip library list --json --limit 50 --offset 0
camelclip library search 'title' --kind video --container mp4 --min-height 1080
camelclip library scan [DIRECTORY] [--recursive]
camelclip library import FILE
camelclip library refresh ASSET_ID
camelclip library remove ASSET_ID --yes
camelclip library delete-file ASSET_ID --yes
camelclip storage profiles list
camelclip storage profiles add
camelclip storage profiles test PROFILE_ID
camelclip storage profiles test-write PROFILE_ID --yes
camelclip storage profiles edit PROFILE_ID --bucket NEW_BUCKET
camelclip storage profiles keys PROFILE_ID
camelclip storage upload ASSET_ID --profile PROFILE_A,PROFILE_B --json
camelclip storage uploads list --json
camelclip storage uploads retry UPLOAD_ID
camelclip storage uploads cleanup UPLOAD_ID --yes
camelclip storage reset --yes
```

TTY prompts hide passwords and credentials. Headless commands accept `--password-fd N` and, for profile creation/key rotation, `--credentials-fd M`, where descriptors >=3 supply a private pipe or owner-only file. Credential input is JSON with `access_key_id`, `secret_access_key`, optional `session_token`. Never put their values into command arguments or shell history. `storage upload` unlocks and executes the selected jobs in that process. Standalone `storage unlock` is a foreground interactive session that locks/exits on Enter; it does not unlock a later separate command. A second process respects the exclusive database lock and reports the existing owner; IPC is not implemented.

## Transfer guarantees and limits

S3 has its own object limit (default two) and bounded multipart concurrency (default two parts per object, configurable 1–4). S3 rate limits are per upload and do not share download budgets. Upload bodies have no fixed total HTTP timeout; response headers have a two-minute timeout. Cancel the operation to stop a stalled transfer. Files >=32 MiB use multipart with >=16 MiB parts, enlarged as necessary to remain within 10,000 parts. File sections stream directly; entire files are not buffered in memory. Before and after sending, a SHA-256 and file identity checks detect changed source data.

Default policy never intentionally overwrites an object. Requests use conditional publication. Custom endpoints first require the explicit write test: it verifies a duplicate conditional write is rejected on a disposable random object and removes that object. Failure to clean up reports its remaining key. Bucket read access alone does not prove write access. HTTP is rejected except an explicitly enabled loopback test endpoint; certificate checks cannot be disabled.

Completed API acknowledgments are checkpointed before remote checking. Recovery can recheck that acknowledged version/ETag and size. When an acknowledgment could not be saved, a collision becomes a conflict instead of blind overwrite. Multipart upload IDs are persisted for cleanup. Durable continuation of individual parts is not implemented: retry starts from the beginning after cleanup. Failed cleanup remains visible and can be retried; provider lifecycle policies are an additional useful safeguard.

Remote results distinguish `uploaded_unverified`, `size_verified`, `checksum_verified`, `verification_failed`. Multipart ETag is never treated as a file MD5. SHA-256 verification is only reported for a supported full-object checksum. Profile destination changes block pending uploads until explicit acceptance; cancellation, failure or profile deletion never removes a local file or completed cloud history. Remote deletion of media objects is not exposed; only explicit test-object and incomplete multipart cleanup are performed.

Tests use a loopback S3 API emulator, including multipart, conditional conflicts, encrypted persistence and independent uploads. No real cloud account/keys are used. Compatibility with each production provider's permissions/checksum variants needs its own acceptance test; a configurable endpoint alone is not a certification of AWS, Yandex, R2, B2 or MinIO behavior. See [AWS conditional writes](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html) and [SDK upload memory/concurrency](https://docs.aws.amazon.com/sdk-for-go/v2/developer-guide/sdk-utilities-s3.html).
